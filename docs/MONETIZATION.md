# 젤리팝 수익화 전략 & 멀티 플랫폼 런칭 (v1, 2026-10-27)

> 한 줄 요약: **광고는 "보고 싶을 때만 보는" 보상형 광고 하나**, 결제는 **"말랑이 후원 팩"(₩3,300, 한 번 구매)** 하나로 시작한다.
> 출시 순서는 **① 웹(젤리독·PWA) → ② Google Play → ③ 토스 앱인토스 → ④ App Store**. 코드는 네 곳 모두 같은 게임 파일 하나를 쓴다.

## 1. 수익 모델

| 수익원 | 어디서 | 방식 | 상태 |
|---|---|---|---|
| 보상형 광고(rewarded) | 실패 화면 "▶ 광고 보고 이어하기" | 끝까지 보면 천장 3칸 올림(시간 끝이면 +20초), 한 판에 1번 | **구현 완료**(계정 ID 넣으면 켜짐) |
| 인앱 구매: 말랑이 후원 팩 | 타이틀 "🎁 후원 팩" | ₩3,300 / $2.99, 한 번 구매(복원 가능) → 광고 없이 이어하기 + 배너 광고 없음 | **구현 완료**(스토어 상품 등록 필요) |
| 배너 광고 | 지도 화면 아래(앱만) | AdMob 배너. 게임 화면은 가리지 않음 | 구현, **기본 꺼짐**(`bannerOnMap`) |
| 자체 배너(하우스 광고) | 플레이 화면 위 배너(banner.js) | 젤리독 다른 앱·이벤트 홍보(무료) | 이미 있음 — 내용만 바꾸면 됨 |
| (후보) 스킨 팩 | 상점 | 말랑이 옷·대포 모양 ₩1,200~2,500 | 그림 작업 필요 → 다음 단계 |
| (후보) 힌트·부스터 | 상점 | 무지개 거품 3개 등(소모형) | 난이도 밸런스 확인 후 |

**왜 이렇게?** 젤리팝은 귀여운 캐주얼 게임이라 강제로 끼어드는 전면 광고(interstitial)는 이탈·나쁜 평점의 주원인이다. 보상형 광고는 플레이어가 선택하므로 만족도를 해치지 않고, 광고 단가도 가장 높다. 후원 팩은 "광고 싫은 사람"을 위한 탈출구다.

**하지 않는 것**: 전면 광고, 확률형 아이템(뽑기), 에너지(하트) 제한, 구독. (아이 이용자 비중이 클 수 있어 정책·평판 위험이 큼)

출처: 앱인토스 개발자 문서(developers-apps-in-toss.toss.im: 사업자 등록·정산·게임 체크리스트·FAQ, 2026-10 확인), Google Play·Apple 수수료는 각 공식 정책 기준(변동 가능). 웹 광고·AdMob 정산 비율은 Google이 경우별로 달라 여기 적지 않음.

## 3. 예상 수익 (계산식 — 숫자는 **가정**)

```
월 광고 수익 ≈ 하루 이용자(DAU) × 1인당 하루 이어하기 광고 횟수 × 30일 × eCPM ÷ 1000
예) DAU 1,000 × 0.8회 × 30 × ₩8,000 ÷ 1000 ≈ ₩192,000/월     (eCPM ₩8,000 = 한국 보상형 광고 단가 가정)
월 결제 수익 ≈ 월 신규 이용자 × 구매 전환율 × ₩3,300 × (1 − 수수료)
예) 3,000명 × 1% × 3,300 × 0.85 ≈ ₩84,000/월
```
→ 처음엔 큰돈보다 **이용자 모으기**가 핵심. 토스(국내 이용자 많음)와 Google Play가 이용자 수를 결정한다.

## 4. 코드 구조 (이미 만들어 둔 것)

| 파일 | 하는 일 |
|---|---|
| `monetize-config.js` | 광고 ID·상품·가격 설정. **Owner가 계정 만든 뒤 빈 칸만 채우면 됨** |
| `monetize.js` | 플랫폼 자동 감지(웹/안드로이드/아이폰/토스/시험) → 광고·결제 공통 함수 `JellyMonetize.rewarded()`, `buy()`, `restore()` |
| `index.html` | 실패 화면 이어하기 버튼, 후원 팩 상점, 광고 중 소리 멈춤, 앱이 뒤로 가면 소리 멈춤, PWA 등록 |
| `manifest.webmanifest`, `sw.js`, `icons/` | 설치형 웹앱(홈 화면에 추가, 오프라인 실행) |
| `app/` | 안드로이드·아이폰 앱 프로젝트(Capacitor) — [docs/LAUNCH.md](LAUNCH.md) |
| `app/toss/` | 토스 앱인토스 미니앱 프로젝트 — [docs/LAUNCH.md](LAUNCH.md) |
| `store/` | 스토어 등록 글(한/영)·아이콘·스크린샷·개인정보처리방침 |

시험: 주소 끝에 `?monetize=mock` → 가짜 광고(2초)·가짜 결제로 흐름 확인. 자동 테스트: `node tests/monetize.test.mjs`.

**알려진 한계**: 구매 확인을 서버 없이 기기 안에서만 한다(영수증 서버 검증 없음). ₩3,300 한 번 구매 상품이라 위험이 작아 1단계는 이대로 가고, 매출이 생기면 영수증 검증 서버(Cloudflare Workers)를 추가한다.
